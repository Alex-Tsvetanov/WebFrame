# HTTP/3 serves a request end to end, and a guard for tests that vanish

## A completed QUIC handshake and an HTTP/3 200

Scratch certificate, server on a scratch port with TLS and HTTP/3 on, two workers,
io_uring backend. `curl -k --http3-only` returns **HTTP 200 over HTTP/3**, body
`Hello, World!`. Then 20 sequential requests, all 200 over h3; then 8 concurrent, all 200
over h3. Server healthy afterwards, both UDP sockets still bound, clean SIGTERM shutdown.

`--http3-only` rather than `--http3`, deliberately: the latter permits fallback, and a TCP
fallback returning 200 would be indistinguishable from success.

**The control.** The same curl against an identically built server with HTTP/3 off: no UDP
socket bound, `--http3-only` fails with code 000, plain `curl` over TCP succeeds with
HTTP/2. So the 200-over-h3 can only have come from the QUIC path. The server's own banner
was never treated as the evidence.

**The limitation, which bounds the claim.** curl's QUIC stack is ngtcp2 and its HTTP/3 is
nghttp3 — the same two libraries this server links. This is not two independent QUIC
stacks. What it establishes is that this project's own HTTP/3 code (cid, packet, headers,
stateless, connection, endpoint) completes a handshake and serves a request to a client
written by someone else. ngtcp2's own reference client has the same property, so
`verify_http3.sh` would not have been stronger on that axis. A genuinely independent check
needs a different stack — quiche, msquic, or a browser.

`verify_http3.sh` was **not** run: its prerequisites are a from-source build of OpenSSL
3.5, nghttp3 and ngtcp2 into `~/opt/quic`, none of which exists here. The system curl made
it unnecessary for this step.

## A guard for tests that do not skip but disappear

On `linux/test-census`. A feature guard around a whole test file does not make its tests
skip — it makes them absent, and Catch2 cannot report what it was never given, so the run
passes and exits 0.

The guard does not forbid dormant tests. It accounts for them: every case the sources
define is attributed either to the running binary or to a named undefined macro, and the
totals must agree. It prints on every run, passing or failing, because a check that only
speaks when it fails is one nobody notices has stopped working.

    test census: 176 registered, 176 expected from 187 defined in tests/
         11 dormant: COROUTE_HAS_HTTP3 is not defined (test_http3_cid.cpp, ...)

Told the same binary that HTTP/3 is on, it fails: "176 registered against 187 expected;
tests vanished with nothing to explain them". Full suite 177/177 on a feature-off tree.

**The problem is wider than HTTP/3.** Eight test files across five macros are guarded this
way, so HTTP/2, TLS and the template tests disappear equally silently on builds without
them.

## Two things the guard caught while it was being written

**A stale binary.** A build directory from 2 September registers one case fewer than the
sources define, with no macro to account for it, because it predates a merged test. That
is the stale-build hazard the harness already refuses runs for, arriving from an unrelated
direction.

**A bug in itself, before it shipped.** CMake passes a target property through `add_test`
as one semicolon-joined argument rather than as a list. The first wiring therefore handed
the script a single string: every macro would have looked undefined, every guarded test
would have been reported dormant on every build, and the check would still have **passed**,
because expected and registered would have agreed. A green check that had stopped
checking — the precise failure its own comment warns about. Found by reading the generated
`CTestTestfile.cmake`; running it would have looked fine. Both argument shapes are now
accepted and both are tested.
