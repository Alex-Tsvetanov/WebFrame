# Re-evaluation under the pacing-covariate rules — pointer only

The laptop re-judged its `transport` and `churn` records with
`benchmark.harness.reevaluate` on `harness/pacing-covariate` (`d83a0b581`). Nothing was
re-run, nothing was timed, no measurement conditions were needed.

**This entry deliberately carries no figures.** The standing convention is that every
report is mirrored here verbatim, but this branch is public and the coordinator asked for
the re-evaluation record to stay in a private paper repository because it names the
campaign. Those two rules conflict, so the resolution is a pointer: the fact of the work
and its location are recorded here so the channel still survives a coordinator handoff;
the numbers are not.

The record is on the private `paper-io-portability` repository, branch
`measure/laptop-2026-09-02`, commit `e9e4dee`, under
`measurements/2026-09-02-laptop/crossarm-reevaluated/`, with a README covering the
refusal tallies by reason, the pacing distributions per rate under both rule sets, and
two naming questions that must be settled before any of it feeds a thesis key.

One item is not campaign data and belongs in the open, because it is a routing fact
another machine needs: **`h1-deep` is not a laptop campaign.** It is
`design_windows_h1_deep` in `run_campaign.py`, documented against `build/windows-tls`.
No `h1-deep` record exists on the laptop. A request for that figure has to go to the
Windows machine; asking the laptop would return a confident zero that actually means
"never run", and in this tool's output those two are the same shape.
